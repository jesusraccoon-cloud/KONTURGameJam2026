# Система сохранений (Checkpoints)

Чекпоинтная система сохранений: 3 точки — **вход в подъезд**, **4/6 кассет**, **6/6 кассет**.
Хранится в памяти (переживает перезагрузку сцены) **и** на диске (`save.json`, переживает перезапуск игры).

Загрузка/респавн = **перезагрузка сцены** → игрок и монстр ставятся на сохранённые позиции →
восстанавливается стадия → «использованные» объекты (триггеры/кассеты) отключаются, чтобы не срабатывать снова.

---

## Файлы (`Assets/Scripts/Save/`)

| Файл | Роль |
|---|---|
| `SC_SaveSystem` | Ядро: память + запись/чтение диска. Static — вешать никуда не надо. |
| `SC_SaveManager` | Менеджер в сцене: чекпоинты, спавн игрока/монстра, загрузка, Continue/New Game. |
| `SC_Saveable` | Компонент на объект, который «запоминается» как использованный. |
| `SC_CheckpointZone` | Триггер-зона чекпоинта (для входа в подъезд). |
| `SC_SaveData` | Структура данных (JSON). Трогать не нужно. |

Файл сейва: `%userprofile%/AppData/LocalLow/<Company>/<Product>/save.json`.

---

## Шаг 1. SaveManager в игровой сцене

Пустой объект `SaveManager` + компонент **`SC_SaveManager`**:

**Player**
- `Player` → `PlayerCapsule` (корень игрока)
- `Player Controller` → его `CharacterController`
- `First Person Controller` → `FirstPersonController` игрока *(чтобы камера не дёргалась после телепорта)*

**Monster**
- `Monster AI` → `MonsterAI` монстра
- `Restore Monster State` → вкл (восстанавливать позицию монстра)

**Checkpoints** → Size = 3:

| Element | Label | Spawn Point | On Restore |
|---|---|---|---|
| 0 (чекпоинт 1) | `Вход в подъезд` | *пусто* | *пусто* |
| 1 (чекпоинт 2) | `4 из 6` | *пусто* | `CassetteInventoryUI.SetCassetteCountDebug` → **4** |
| 2 (чекпоинт 3) | `6 из 6` | *пусто* | `CassetteInventoryUI.SetCassetteCountDebug` → **6** |

> **Spawn Point оставляй пустым** — позиция игрока запоминается автоматически в момент чекпоинта.
> `SetCassetteCountDebug(4/6)` восстанавливает и счётчик, и стадию (монстр, двери, финал).

**New Game**
- `Gameplay Scene Name` → имя игровой сцены.

## Шаг 2. Триггеры чекпоинтов

**Чекпоинт 1 — вход в подъезд:** зону-триггер `SC_CheckpointZone` (Checkpoint Index = 1) поставь у входа в подъезд.

**Чекпоинт 2 — 4/6:** на `CassetteInventoryUI`, событие **On Reached Four Of Six ()** → `SaveManager.SaveCheckpoint` → число **2**.

**Чекпоинт 3 — 6/6:** событие **On Reached Six Of Six ()** → `SaveManager.SaveCheckpoint` → **3**.

Автосейв срабатывает сам при сборе 4-й и 6-й кассеты.

## Шаг 3. «Использованные» объекты (чтоб не срабатывали повторно)

На каждый такой объект — **`SC_Saveable`** (ID генерится сам).

- **Кассеты** (`CassettePickup`) и **`UniversalScenarioTrigger`** — помечают и прячут/глушат себя **полностью автоматически**.
  Достаточно просто добавить `SC_Saveable` на объект. Ничего вешать не нужно.
- Остальным объектам нужно повесить **`MarkUsed`** на событие «объект использован» (см. таблицу).

Что сделать при загрузке — компонент делает **сам** через поле **`Restore Action`** (вручную `SetActive` НЕ нужно).

| Объект | MarkUsed | Restore Action |
|---|---|---|
| `CassettePickup` (кассета) | **авто** (ничего вешать не надо) | **Disable Game Object** *(дефолт)* |
| `UniversalScenarioTrigger` | **авто** (ничего вешать не надо) | не важно — триггер глушит себя сам |
| `SC_AudioTrigger` | `On Player Entered ()` → `SC_Saveable.MarkUsed` | **Disable Colliders** |
| `ThreeStageInteractableObject` | `On Destroyed ()` → `MarkUsed` | **Event Only** → см. ниже |

**Restore Action** (что сделать при загрузке, если объект уже был использован):
- **Disable Game Object** — спрятать объект целиком (кассеты, разовые предметы). *По умолчанию.*
- **Disable Colliders** — выключить все коллайдеры (триггер остаётся в сцене, но больше не срабатывает).
- **Event Only** — ничего автоматически, всё вручную через `On Restore Used`.

Поле `On Restore Used` теперь **опционально** — только для особых случаев (в дополнение к Restore Action).

> ⚠️ **ThreeStageInteractableObject:** НЕ ставь ему `Disable Game Object` (иначе объект исчезнет).
> На **родителе** ставь `Restore Action = Event Only`, `On Restore Used → ThreeStageInteractableObject.ForceSetStage` = **2**,
> а `MarkUsed` вешай на **`On Destroyed ()`** (не на `On Interact`). На дочерних `StageWhole/StageBroken/StageDestroyed`
> компонент `SC_Saveable` **не нужен** — их стадию задаёт родитель.

> Скопировал объект с `Saveable`? Контекстное меню компонента → **New Id** (чтобы не было дублей).

## Шаг 3b. Объекты с состоянием (стадия / дверь / радио / замена)

Эти объекты хранят не «использован да/нет», а конкретное **состояние**. Они сохраняются **сами** — достаточно
повесить на объект компонент **`SC_Saveable`** (ID сгенерится сам). **Ничего вешать/настраивать не нужно**,
`Restore Action` у их `SC_Saveable` не важен (эти скрипты используют своё числовое состояние, а не «used»).

| Объект | Что сохраняется |
|---|---|
| `ThreeStageInteractableObject` | текущая стадия (0/1/2) — после загрузки объект в той же стадии |
| `RadioCassettePuzzle` | кассета открыта / радио взорвано (сломанная модель) |
| `UniversalDoor` | открыта/закрыта + заперта (полотно встаёт мгновенно, без анимации) |
| `ReplaceObjectOnInteract` | факт замены (объект остаётся заменённым) |

> Для `ThreeStageInteractableObject` теперь **не нужно** ни `On Destroyed → MarkUsed`, ни `ForceSetStage` в `On Restore Used` —
> стадия сохраняется автоматически. `SC_Saveable` на дочерних `StageWhole/StageBroken/StageDestroyed` **не нужен**, только на родителе.
> Для `UniversalDoor` сохранение включается только если на двери есть `SC_Saveable` — двери без него ведут себя как раньше.

Нюанс: состояние живёт «вживую» и снимается снимком в момент чекпоинта (как и список used). Если изменить объект уже
**после** чекпоинта, при загрузке восстановится его последнее состояние — так же, как с собранными кассетами.

---

## Шаг 4. Смерть игрока → загрузка

На экране смерти / кнопке вызови **`SC_SaveManager.ReloadLastCheckpoint()`** — сцена перезагрузится на последний чекпоинт.

---

## Шаг 5. UI меню

В сцене меню поставь объект с **`SC_SaveManager`** (Player/Checkpoints можно не заполнять). Кнопки:

- **Continue** → `SC_SaveManager.ContinueFromDisk()`. Показывать/включать по **`HasSave()`**.
- **New Game** → `SC_SaveManager.NewGame()` (стирает сейв, грузит игровую сцену).

---

## API `SC_SaveManager`

| Метод | Что делает |
|---|---|
| `SaveCheckpoint(int index)` | Сохранить чекпоинт (1/2/3) + позицию игрока и монстра |
| `ReloadLastCheckpoint()` | Перезагрузить сцену на последний чекпоинт (смерть) |
| `ContinueFromDisk()` | Загрузить сейв с диска и перейти в сохранённую сцену (меню) |
| `NewGame()` | Стереть сейв и начать заново |
| `HasSave()` → bool | Есть ли сейв на диске (для кнопки Continue) |

---

## Что сохраняется

- Номер чекпоинта + подпись + сцена + время.
- Позиция и поворот **игрока**.
- Позиция, поворот и активность **монстра** (телепорт через `NavMeshAgent.Warp`).
- Список ID «использованных» объектов.
- Числовое состояние объектов по ID (стадия `ThreeStage`, флаги радио, открыта/заперта дверь, факт замены).

## Нюансы

- Восстановление применяется **через кадр после загрузки** сцены (чтобы всё проинициализировалось).
- Монстр восстанавливается только если на чекпоинте был активен; позиция ставится **после** восстановления стадии.
- Кассета помечается `MarkUsed` **до** `AddCassette`, поэтому автосейв на 4/6 уже видит её собранной.
- Счётчик кассет восстанавливается через `SetCassetteCountDebug` в `On Restore` чекпоинта (собранные кассеты — `Saveable`, заново не подберутся).
