# Сохранение объектов с состоянием (ThreeStage / Radio / Door / Replace)

Инструкция по сохранению для четырёх типов объектов, у которых важно **состояние**, а не просто факт «использован»:

- `ThreeStageInteractableObject` — стадия 0/1/2 (целый → повреждённый → уничтоженный)
- `RadioCassettePuzzle` — кассета открыта / радио взорвано
- `UniversalDoor` — открыта/закрыта + заперта
- `ReplaceObjectOnInteract` — объект заменён

После загрузки чекпоинта каждый такой объект сам возвращается в то состояние, в котором был.

---

## Как это работает (общий принцип)

Все четыре скрипта уже доработаны и умеют сохранять себя **сами**:

1. при старте сцены находят на себе компонент **`SC_Saveable`** и берут его `id`;
2. при изменении состояния (сломали, открыли, взорвали, заменили) пишут состояние в сохранение;
3. в своём `Start` читают сохранённое состояние и сразу приводят себя к нужному виду.

**От тебя нужно только одно: повесить на объект компонент `SC_Saveable`.**
Никакие события (`MarkUsed`, `On Restore Used`) и поле `Restore Action` для них настраивать **не нужно** —
эти скрипты используют собственное числовое состояние, а не список «used».

> Состояние хранится по `id` из `SC_Saveable`. Поэтому ID должен быть **уникальным** у каждого объекта
> (генерируется автоматически; после копирования объекта — см. раздел «Копирование» ниже).

---

## Предусловие: система сохранений в сцене

Чтобы восстановление вообще происходило, в сцене должен быть настроен **`SaveManager`** и хотя бы один чекпоинт
(см. `SAVE_SYSTEM.md`, Шаги 1–2). Объекты ниже восстанавливаются при загрузке чекпоинта (смерть / клавиша `N` / Continue).

---

## 1. ThreeStageInteractableObject

**Что сохраняется:** текущая стадия (0 — целый, 1 — повреждённый, 2 — уничтоженный).
После загрузки объект стоит в той же стадии, включая действия уничтожения (`Objects To Enable/Disable When Destroyed`).

**Настройка:**
1. На **родительский** объект (где висит `ThreeStageInteractableObject`) добавь компонент **`SC_Saveable`**.
2. Больше ничего настраивать не нужно.

**⚠️ Обязательная чистка (если настраивал раньше по-старому):**
- **Сними `SC_Saveable` с дочерних** объектов-стадий `StageWhole`, `StageBroken`, `Stage destroyed`.
  `SC_Saveable` должен остаться **только на родителе**.
  *(Иначе дочерний объект попадёт в список «used», и его спрячет `Disable Game Object` — визуал стадии сломается.)*
- Убери со скрипта старые привязки: `On Interact → MarkUsed`, `On Destroyed → MarkUsed`,
  `On Restore Used → ForceSetStage`. Теперь стадия сохраняется автоматически.

**Нюанс:** список «включаются по одному» (`Objects To Activate`) восстанавливается не по шагам, а по итоговой стадии —
для баррикад/ваз этого достаточно. Основной визуал и destroyed-действия восстанавливаются корректно.

---

## 2. RadioCassettePuzzle

**Что сохраняется:** «кассета была открыта» и «радио взорвалось».
После загрузки: если радио взорвано — показывается сломанная модель (`Broken Radio Object`), целая скрыта, музыка не запускается;
если кассета была открыта — она не прячется повторно.

**Настройка:**
1. На объект радио (где висит `RadioCassettePuzzle`) добавь компонент **`SC_Saveable`**.
2. Больше ничего.

**Важно:** сама видеокассета из радио — это отдельный объект (`CassettePickup`). Если игрок её уже забрал,
она прячется своей собственной логикой сохранения (у `CassettePickup` тоже должен быть `SC_Saveable`).
Радио отвечает только за своё состояние (взрыв/разблокировка), кассета — за своё (собрана/нет).

---

## 3. UniversalDoor

**Что сохраняется:** открыта/закрыта + заперта (`isLocked`).
После загрузки полотно **мгновенно** встаёт в сохранённое положение (без анимации открытия), проход в NavMesh синхронизируется.

**Настройка:**
1. На дверь (где висит `UniversalDoor`) добавь компонент **`SC_Saveable`** — **только тем дверям, которые нужно сохранять**.
2. Двери **без** `SC_Saveable` работают как раньше и не сохраняются.

**Нюансы:**
- Таймеры (`Auto Close`, запрет открытия через E) при загрузке сбрасываются — сохраняется только итоговое положение.
- Отдельная зона взаимодействия (`Door Interact Zone`) — это дочерний объект-форвардер, `SC_Saveable` на неё вешать не нужно.

---

## 4. ReplaceObjectOnInteract

**Что сохраняется:** факт замены (объект уже заменён на другой / выключен).
После загрузки: включены объекты из `Objects To Enable`, выключены из `Objects To Disable` (или сам объект выключен,
если список пуст и стоит `Disable This Object If Disable List Empty`), коллайдер взаимодействия отключён.

**Настройка:**
1. На объект (где висит `ReplaceObjectOnInteract`) добавь компонент **`SC_Saveable`**.
2. Больше ничего.

---

## Копирование объектов (важно!)

`id` в `SC_Saveable` генерируется один раз. Если ты **дублируешь** объект (Ctrl+D) — копия унаследует тот же ID,
и два объекта будут делить одно состояние (одно сломается/откроется → второе тоже «восстановится» неправильно).

**Решение:** у скопированного объекта в компоненте `SC_Saveable` нажми контекстное меню (три точки / ПКМ по компоненту) →
**`New Id`**. Так каждому объекту достанется свой уникальный ID.

---

## Быстрая проверка

1. Пройди до чекпоинта (вход в квартиру / 4 из 6 / 6 из 6).
2. Измени объект: сломай `ThreeStage`, взорви радио / забери кассету, открой дверь, сработай заменой.
3. Нажми **`N`** (дебаг-загрузка последнего чекпоинта).
4. Объект должен остаться в **изменённом** состоянии, а не сброситься к исходному.

> Старые сейвы состояния объектов не содержат — тестируй с **нового** прохождения (или сотри `save.json`).
